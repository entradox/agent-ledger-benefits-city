# Deploying Benefits City into the Railway in-house hub

Hey — this is the dev-to-dev handoff for deploying **Benefits City** (US bank
account + credit card signup bonus feed, an AI Agent City project) as a new
service inside your existing Railway hub, served at
**`https://aiagentscity.com/benefits`**.

No code changes needed. The repo is a standard Node 20+ service: one build
command, one start command, one native dep (better-sqlite3, for metrics), stateless apart from a JSON file
it seeds itself.

**What "done" looks like:**

- `https://aiagentscity.com/benefits/` → landing page, live stats
- `https://aiagentscity.com/benefits/bonuses` → filterable browse page
- `https://aiagentscity.com/benefits/agents` → agent docs, showing the
  `https://aiagentscity.com/benefits/mcp` endpoint
- `https://aiagentscity.com/benefits/api/stats` → JSON feed stats
- `https://aiagentscity.com/benefits/mcp` → answers MCP clients (Streamable HTTP)
- `https://aiagentscity.com/benefits/healthz` → `{"status":"ok",...}` (for
  uptime monitors)

## 2. Add the service to your Railway hub

1. Push this repo to GitHub (any org/repo name you like).
2. In your existing Railway project: **New → GitHub Repo →** pick it.
3. Service **Settings → Build**: Build Command `npm run build`
   (Railway usually detects it; set it explicitly if not).
   **Deploy**: Start Command `npm start`.
4. **Variables** — set exactly these:

   | Var | Value | Notes |
   |---|---|---|
   | `BASE_PATH` | `/benefits` | **Required.** Every internal link, asset path, form action, and the MCP/API routes follow this. Requests outside the prefix 404. |
   | `PUBLIC_URL` | `https://aiagentscity.com/benefits` | **Required.** Canonical public URL baked into the agent docs, `llms.txt`, and the `/api` descriptor. Without it, docs show the Railway origin URL. |
   | `PORT` | *(leave alone)* | Railway injects it. |
   | `TRUSTED_PROXY_HOPS` | `2` when served through the aiagentscity.com hub (hub edge + this service's edge); `1` (default) for direct traffic | Number of proxies that append to `X-Forwarded-For`. Metrics take the client IP that many entries from the right; entries further left are client-written and ignored. |
   | `RATE_LIMIT_PER_MIN` | `0` (off) unless set; e.g. `120` | Per-visitor request cap per minute; over-cap requests get `429` + `Retry-After`. **Set this only together with the correct `TRUSTED_PROXY_HOPS`** — keys come from the same XFF logic, so with hops unset every hub-proxied visitor shares one bucket and the limit throttles everyone together. `/healthz` is exempt. |
   | `BONUS_DB_PATH` | *(leave unset)* | Only if you want the JSON store somewhere other than `data/bonuses.json`. |

5. Deploy. Note the Railway origin URL
   (`https://<service>-production-xxxx.up.railway.app`) — you need it for the
   proxy rule below.

Smoke-test the origin directly (it serves the app **under the `/benefits`
subpath**, not at root):

```bash
curl -s https://<railway-origin>.up.railway.app/benefits/healthz
# → {"status":"ok","service":"benefits-city","offers":29,...}
curl -s https://<railway-origin>.up.railway.app/benefits/api/stats | head -c 200
```

**Already handled in the repo:** `start` script, `PORT` respected,
`engines: node >= 20`, `prestart` seeds the DB.

## 3. Reverse-proxy `aiagentscity.com/benefits` → Railway

The app expects the `/benefits` prefix (that's what `BASE_PATH` is for), so the
proxy forwards the **full path unchanged** — no path rewriting. Set
`x-forwarded-proto: https` so the app derives `https://` URLs correctly (belt
and suspenders alongside `PUBLIC_URL`). The proxy must also **append** the client IP to
`X-Forwarded-For` (as below); `TRUSTED_PROXY_HOPS=2` assumes it does, otherwise metrics see
every visitor as the proxy.

**Option A — Cloudflare Worker** (route `aiagentscity.com/benefits*`):

```js
export default {
  async fetch(request, env) {
    const url = new URL(request.url);
    if (url.pathname === "/benefits" || url.pathname.startsWith("/benefits/")) {
      const upstream = new URL(
        url.pathname + url.search,
        "https://<railway-origin>.up.railway.app", // <-- from step 2
      );
      const headers = new Headers(request.headers);
      headers.set("x-forwarded-proto", "https");
      const xff = request.headers.get("x-forwarded-for");
      const ip = request.headers.get("cf-connecting-ip") ?? "";
      headers.set("x-forwarded-for", xff ? `${xff}, ${ip}` : ip);
      headers.set("host", upstream.host);
      return fetch(
        new Request(upstream, {
          method: request.method,
          headers,
          body: request.body,
          redirect: "manual",
        }),
      );
    }
    return fetch(request); // everything else → the main site, untouched
  },
};
```

**Option B — nginx** (if you terminate TLS yourself):

```nginx
location /benefits {
    proxy_pass https://<railway-origin>.up.railway.app;
    proxy_set_header Host $proxy_host;
    proxy_set_header X-Forwarded-Proto https;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_http_version 1.1;
}
```

**Option C — Vercel** (if the main site is on Vercel), in `vercel.json`:

```json
{ "rewrites": [{ "source": "/benefits/:path*", "destination": "https://<railway-origin>.up.railway.app/benefits/:path*" }] }
```

## 4. How the subpath resolves (so you can sanity-check)

| Public URL | What it is |
|---|---|
| `/benefits/` | Landing, live stats from the real data |
| `/benefits/bonuses` | Browse + filters (`?type=&state=&min=&dd=&q=&sort=`) |
| `/benefits/bonuses/:id` | Bonus detail (requirements, expiry countdown, source) |
| `/benefits/agents` | MCP docs with copy-paste client configs |
| `/benefits/about` `/disclosure` `/contact` | About, FTC disclosure, contact |
| `/benefits/mcp` | **MCP over Streamable HTTP** (`POST`, stateless, no auth). Also `npm run mcp` for local stdio. |
| `/benefits/api/bonuses.json` | Full feed (what aggregator agents poll) |
| `/benefits/api/bonuses/:id` | One record |
| `/benefits/api/stats` | Live counts, total bonus value, expiring list |
| `/benefits/api` | Service descriptor (also documents the MCP endpoint) |
| `/benefits/llms.txt` | Dynamic agent manifest, host-aware |
| `/benefits/healthz` | Health check → `{"status":"ok","service":"benefits-city","offers":N}` |
| `/benefits/assets/site.css` | The one static asset |

The MCP endpoint speaks JSON-RPC over `text/event-stream` responses. A bare
`tools/list` without the `initialize` handshake returns a protocol error —
that's correct MCP behavior, not a bug. Full check:

```bash
curl -s -X POST https://aiagentscity.com/benefits/mcp \
  -H 'Content-Type: application/json' \
  -H 'Accept: application/json, text/event-stream' \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize",
       "params":{"protocolVersion":"2025-06-18","capabilities":{},
                 "clientInfo":{"name":"probe","version":"1"}}}' \
  | grep -o '"name":"benefits-city"'
```

## 5. Data refresh — how the feed stays fresh

Full process in `REFRESH_PLAN.md`. The short version for you as operator:

- **To update the live feed:** edit `seed-data/*.json` (bump
  `last_verified_date`, change terms, or remove dead offers), commit, push.
  Railway redeploys; `prestart` re-seeds the JSON store automatically.
- **Cadence:** offers expiring within 30 days re-checked weekly
  (`node dist/cli.js expiring --days 30` is the priority queue); full feed
  monthly. No record should be served with `last_verified_date` older than
  30 days.
- **Provenance rules:** official bank offer pages first; where official pages
  block bots (Chase, Wells Fargo, Fifth Third, Amex are known bot-blockers),
  3+ reputable aggregator consensus counts as verified — never treat a bot-error
  page as an expired offer. Respect robots.txt; no scraping of sites that
  disallow bots.

## 7. Ops notes

- Logs: Railway dashboard → service → Logs. Startup prints the bound URLs;
  request errors go to stdout.
- The JSON store is single-node with atomic writes — fine at this scale. Move
  to Postgres/SQLite if concurrent writers ever appear.
- No secrets, no API keys, no cookies, no per-user records. The only env vars
  that matter are `PORT`, `BASE_PATH`, `PUBLIC_URL`.
- Contact for data corrections: `bonuses@aiagentscity.com` (shown on
  `/benefits/contact`).
