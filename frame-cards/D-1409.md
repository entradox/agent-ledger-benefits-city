## Deviation found during recon (reported, not silently worked around)

The brief says "use whatever engine the service already runs — confirm in your reply".
**There is no database engine.** `src/db.ts` is a JSON file store (`data/bonuses.json`).
So there was nothing to reuse. Chose `better-sqlite3` (standard, prebuilt binaries,
works on the app's declared Node >=20) over `node:sqlite` (experimental, needs Node 22.5+,
and the app does not pin a runtime that guarantees it).

**Consequence that would have silently broken the feature:** a DB on the container
filesystem is wiped on every deploy — metrics would appear to work, then reset to zero
each release. Fixed by attaching a dedicated Railway volume
(`benefits-city-volume` → `/data`) and setting `METRICS_DB_PATH=/data/metrics.sqlite`.
